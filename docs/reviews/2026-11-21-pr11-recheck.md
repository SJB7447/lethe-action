## 결론

**P2 2건이 남아 있어 수정 후 재확인이 필요하다.** 기존 CHAIN-1·EVT-1·FX-1은 해결됐다. CAM-1의 렌더 카메라 좌표 불일치는 해결됐지만, 변경된 호출 순서가 현재 마우스 입력을 한 프레임 늦게 판정하는 회귀를 만든다.

퍼펙트 A안은 문서에 적힌 입력 간격 규칙을 구현하고 있다. 그러나 그 규칙 자체가 성공한 직전 공격까지 연타로 계산하므로, 요청한 “정상적인 빠른 연쇄를 잘못 막지 않음”은 충족하지 못한다. 아래 A-1은 문서와 코드의 불일치가 아니라 요구 동작과 현 규칙의 충돌이다.

## 발견 사항

### CAM-1-R — [P2] 마우스를 옮기며 공격하면 이전 포인터 방향으로 대상을 선택한다

- 위치: `src/scenes/LabScene.ts:87–99` (핵심 `:90`, `:98`)
- 관련: `src/scenes/LabScene.ts:105–111`, `src/game/sim.ts:972–978`, `src/game/sim.ts:639–643`

`input_.poll()` 이후 바로 `sim.frame()`을 실행하고, 현재 포인터를 월드 좌표로 바꾸는 `syncView()`는 그 뒤에 실행한다. 따라서 새 클릭은 이번 프레임에 소비하지만, 대상 선택과 록온은 이전 프레임의 `aimWorld`로 진행한다. “지난 화면의 카메라 변환”을 사용하는 것과 “지난 마우스 위치”를 사용하는 것은 구분해야 한다.

실제 Phaser 씬의 루프를 정지하고 한 번의 `LabScene.update(…, 1000/120)`를 실행했다. 플레이어 중심 x=400, 양쪽에 열린 조각을 가진 적을 배치하고, 직전 포인터 `(600,291)`에서 현재 `(200,291)`로 옮긴 뒤 공격을 입력했다. 기대는 왼쪽 적(id=6)이지만 실제 `strikeTarget`은 오른쪽 적(id=7)이었다. 업데이트가 끝난 뒤에는 `aimWorld=(205,291)`로 갱신되어 안내만 새 방향을 가리킨다. 카메라 FX를 꺼도 재현된다.

영향: 빠르게 조준 방향을 바꾸며 클릭하면 의도하지 않은 조각으로 돌진한다. 프레임이 길어질수록 이전 조준을 사용하는 시간이 커진다.

권장: 시뮬레이션 전에 현재 포인터를 현재 표시된 카메라 행렬로 변환한다. 시뮬레이션 후 카메라 갱신·`preRender()`·안내 갱신은 유지하여 렌더 좌표 보정도 보존한다.

### A-1 — [P2] 성공한 공격 뒤의 빠른 정상 연쇄까지 연타로 판정한다

- 위치: `src/game/sim.ts:662–664`
- 관련: `src/game/sim.ts:254–259`, `src/core/tuning.ts:17`, `docs/EVENTS.md:20`

`beginStrike()`는 사용된 입력의 `lastFreePressReal`만 지우고, `pressReal` 기록은 유지한다. 다음 공격에서 `pressReal - prevPressReal >= perfectMashGuard`를 검사하므로 직전 입력이 성공한 파고들기였는지, 중간에 헛클릭이 있었는지 구분하지 않는다. 기본값 0.15초보다 빠른 정상 연쇄는 퍼펙트에서 제외된다.

실제 `Sim.frame(1/120)`을 사용한 재현:

1. 벽 없는 통제 환경에 플레이어 `(100,100)`, 적 `(110,100)`, 다음 적 `(170,100)`을 둔다. 나머지 전투 튜닝은 기본값을 사용한다.
2. 첫 적의 조각을 열고 공격을 한 번 누른다. 첫 타격은 `perfect:true`이며 다음 조각이 열린다.
3. 추가 입력 없이 기다렸다가 다음 조각이 열린 뒤 한 번만 공격한다. 두 입력 간격은 **0.108333초**, 다음 조각의 `openedAt=0.008333`, 새 입력의 게임 시각은 `0.033333`이다. 선입력이 아니며, 공격 시 퍼펙트 시간도 남아 있다.
4. 결과는 첫 타격 `perfect:true`, 두 번째 타격 **`perfect:false`**다. 입력 간격만 **0.183333초**로 늘리면 두 번째도 `perfect:true`다.

영향: 정상 연쇄 자체는 이어지고 이미 켜진 `perfectMode`도 유지된다. 다만 빠르게 반응한 타격의 퍼펙트 보너스·이벤트·연출이 일반 타격으로 낮아진다. 이를 “연쇄 전체가 끊김”으로 해석하면 안 된다.

현 `docs/EVENTS.md:20`의 “바로 전 입력과의 간격” 설명과는 일치한다. 정상적인 빠른 연쇄를 허용하려면, 성공적으로 소비된 공격과 미사용/중복 입력을 구분하도록 판정과 문서를 함께 조정해야 한다. 단순히 guard 기본값만 낮추면 튜닝값이나 적 간격에 따라 같은 문제가 다시 생긴다.

## 퍼펙트 A안 및 이벤트 확인

| 항목 | 확인 결과 |
|---|---|
| 조각 열린 뒤 첫 정상 입력 | `perfect:true`로 타격하고 `perfect:start` 발행. |
| 파고드는 중 다음 조각을 미리 누름 | 실제 프레임 진행에서 다음 타격은 `perfect:false`. 공격 자체는 일반 타격으로 소비된다. |
| 열리기 직전 헛공격 | `openFragment()`에서 해당 조각의 `perfectTimer=0`이 됨을 재현했다(`src/game/sim.ts:606–607`). |
| 짧은 입력 간격 | 0.15초 미만은 제외된다. 문서대로지만 정상 연쇄도 제외하는 A-1이 있음. |
| 퍼펙트 판정 확정 시점 | 시작 시 `strikePerfect`로 저장(`:662–663`), 적중 시 그 값을 `strike:hit.perfect`로 전달(`:702–706`). 적중 순간 타이머로 다시 판정하지 않는다. |
| 시간 축 | 입력 간격은 `realClock`, 조각 개방 및 선입력 비교는 게임 시간 사용. 히트스톱 중에도 공격을 수집하고 realClock은 진행하지만 고정 스텝과 perfectTimer는 멈춘다(`:240–278`). |
| 이벤트 형식 | `src/core/events.ts`와 `docs/EVENTS.md`의 perfect 관련 이벤트 이름·payload는 일치한다. 비퍼펙트 후속 타격만으로 perfect 모드를 끝내지 않는 것도 현재 종료 계약과 일치한다. |

## 검증 범위와 한계

- 원본 작업 트리 대신 대상 커밋의 격리된 스냅샷에서 검사했다. 저장소 소스와 브랜치는 바꾸지 않았다.
- `npm run build`: **통과** (`tsc --noEmit`, Vite production build). 번들 500KB 초과 안내가 있었으며 빌드 실패는 아니다.
- 실제 Sim 코드와 기본 전투 튜닝을 사용하는 임시 Node 재현으로 빠른/느린 정상 입력, 선입력, 개방 직전 헛공격, 원거리 타격, reset 이벤트, FX 시간 튜닝을 확인했다. 적 배치와 초기 조각 개방은 통제된 테스트 조건이다.
- 로컬 Vite 앱을 Chrome/Playwright로 실행하여 실제 Phaser 씬의 포인터·대상 선택 및 카메라 확대·밀림 좌표를 검증했다. 테스트에서 씬 루프를 정지하고 업데이트를 직접 호출했다.
- 카메라 재현에서 저장된 월드 조준점 `(273.307658,288.201926)`은 변환 결과와 일치했다. viewRect `(99.955993,35.975246,832.088014,468.049508)`도 worldView와 일치했다. 1초 히트스톱을 1/60초 진행한 값은 `0.983333`이었다.
- 장시간 수동 플레이, 모든 튜닝 조합, 저사양 기기의 성능/시각적 손맛은 검증하지 않았다. A-1의 규칙 변경 후 체감 조정은 사람의 플레이 확인도 필요하다.
- 산출물은 이 리뷰 문서뿐이며 커밋·push는 하지 않았다.
