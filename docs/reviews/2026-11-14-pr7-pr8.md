## PR #8 — claude/gaze-perception

### PER-1 · P2 — 벽 표면에서 바깥으로 향하는 레이까지 거리 0으로 차단한다

- 위치: **`src/game/perception.ts:36-40`** (관련 `:18-19`, `src/game/sim.ts:350`).
- 시작점이 경계에 있고 레이가 벽에서 멀어지면 slab의 진입값은 음수, 이탈값은 0이다. `tmin`을 0으로 시작하고 `tmin > tmax`만 배제하므로 `[0,0]` 접촉을 앞쪽의 충돌로 취급한다. 모서리에서 바깥으로 나갈 때도 같다.
- 실제 함수 재현: 벽 `{x:0,y:0,w:100,h:20}`, 원점 `(50,0)`, 방향 `(0,-1)`, 최대 거리 130 → **0**, 기대 130. `(50,0)`에서 `(50,-80)`으로 `hasLineOfSight`는 **false**다. 모서리 `(0,0)`에서 `(-√½,-√½)` 방향도 0이다. 안쪽 방향 `(0,1)`의 0은 정상이다.
- 게임 경로도 있다. 지상 점프 소리는 `p.y + p.h`에서 생성하므로 발판 표면에 정확히 놓인다. 반경 130, wallFactor 0.4일 때 벽 바깥 위쪽 80px 대상도 `hears=false`가 되어, 실제로 막힌 벽 없이 점프 소리가 감쇠된다.
- 권고: 출발점의 접촉과 전방에서 벽 내부로 들어가는 교차를 구분한다. 바깥/안쪽/평행/모서리 출발을 함께 검사한다. 시작점이 벽 내부이면 해당 벽을 무시하는 기존 명시적 정책과는 별개 문제다.

### PER-2 · P2 — 48방향 다각형이 모서리 주변의 hears 판정과 다르다

- 위치: **`src/game/perception.ts:108-117`** (관련 `src/game/sim.ts:951`, `src/scenes/placeholderArt.ts:213-216`).
- `hears`는 대상 방향으로 정확한 레이를 쏘지만 `soundShape`는 7.5° 간격의 표본을 직선으로 연결한다. 벽 모서리의 급격한 도달거리 변화가 표본 사이에 있으면 경계를 건너 연결하므로, 같은 `soundReach`를 호출해도 표시 영역은 같은 판정이 아니다.
- 재현: 소리 `(0,0)`, 반경 130, wallFactor 0.4, 벽 `{x:50,y:3,w:10,h:100}`, rays=48. 대상 **`(90,5)`는 다각형 내부지만 `hears=false`**다. `(128,0.5)`는 반대로 다각형 밖이지만 `hears=true`다. ray-casting point-in-polygon 검사로 확인했다. 이는 아래 PER-3의 성장 애니메이션을 제거한 완전히 펼쳐진 모양에서도 발생한다.
- 영향: 표시를 보고 소리가 닿는다고 판단해도 적이 반응하지 않거나 범위 밖으로 보이는 적이 반응한다. `SoundView.points`와 ART_GUIDE의 '판정과 같은 모양' 계약을 충족하지 못한다.
- 권고: 모서리 각도 양옆을 포함해 도달거리 불연속을 표현하거나, 판정과 표시가 동일한 기하 영역을 사용하도록 한다. 원호를 유한 다각형으로 표시할 때의 허용 오차도 정의할 필요가 있다.

### PER-3 · P2 — 청각 판정은 즉시 전체 범위인데 그림만 축소해서 시작한다

- 위치: **`src/scenes/placeholderArt.ts:48-52`** (관련 `src/game/sim.ts:951-960`).
- `emitSound`는 발생 즉시 전체 반경으로 적을 `heard` 상태로 바꾼다. 반면 렌더러는 최초 수명의 25% 동안 `points`를 중심으로 축소해 그린다. 벽이 없어도 표시와 판정이 다르며, 벽에 맞춰 잘라 놓은 지점까지 중심 방향으로 옮겨진다.
- 실제 렌더 함수에 Graphics 기록 객체를 넣은 결과: 수명 0.6초, 발생 후 0.05초, 반경 100 → 화면 외곽의 최대 반경 **33.33px**. 같은 시점 80px 대상의 `hears`는 **true**이며 판정은 이미 발생 때 적용된다. 기본값에서 첫 0.15초 동안 이 불일치가 있다.
- 권고: 정확한 범위 외곽선을 처음부터 보여 주고 별도 파동을 애니메이션하거나, 게임 판정도 파동 도달 시점과 일치시킨다. PER-2를 고쳐도 이 시간상 불일치는 남는다.

### PER-4 · P2 — heard → alert에서 문서상 '평상시 → 알아챔 한 번' 이벤트가 다시 발생한다

- 위치: **`src/game/sim.ts:933`** (관련 `:955-960`, **`docs/EVENTS.md:23`**).
- 문서는 `enemy:notice`를 '평상시 → 알아챔으로 바뀔 때 한 번'이라고 명시한다. 소리로 `idle → heard`가 되어 이미 알아챈 적도, 시야로 확인되면 `awareness !== 'alert'` 조건 때문에 `sight` 이벤트를 다시 보낸다. `heard`에서의 재발각 역시 같다.
- 실제 Sim에서 소리를 들려준 뒤 같은 적을 플레이어 쪽으로 향하게 하여 `perceive` 호출: **`sound`, `sight` 두 이벤트**. 계속 보이는 동안 추가 이벤트는 없었다. 소리 발생과 적 갱신은 한 fixed step 안에서도 이어질 수 있어 같은 틱에 두 알림을 받는 상황이 가능하다.
- 영향: 문서대로 최초 인식 한 번을 기대하는 UI/효과음 소비자가 연속 알림을 받을 수 있다. 현재 상태 전환 자체가 틀렸다고 단정하는 것이 아니라 **문서와 구현의 발행 조건 불일치**다.
- 권고: 인식 단계 상승마다 알림을 보내는 의도라면 `idle → heard`, `idle/heard → alert`를 문서에 명시한다. 현재 계약을 유지하려면 발행 조건을 그 계약에 맞춰 제한한다.

### PER-5 · P2 — 키보드 방향 전환 프레임에 이전 시선으로 록온이 차오른다

- 위치: **`src/game/sim.ts:203-206`** (관련 `:321`, `:887-889`, `:516`).
- `updateGaze()`는 렌더 프레임 시작에 한 번만 실행된다. `aimSource='none'`이면 당시의 `p.facing`을 읽는다. 실제 새 입력으로 몸 방향을 바꾸는 것은 그 뒤 fixed step의 `updatePlayer()`다. 같은 프레임의 `updateLock()`은 이전 방향의 `p.gaze`를 사용한다.
- 재현: 오른쪽을 보고 있는 플레이어 `(100,100)`, 오른쪽 적 `(220,100)`, 벽 없음, 수동 록온 누름. 키보드 왼쪽 입력 후 `frame(1/60)` → **`facing=-1`, `gaze=0`, 적 lockProgress=0.083333**. 몸은 왼쪽으로 돌았지만 오른쪽 적에게 진행도가 생겼다. 시선 원뿔 그림도 그 프레임에는 이전 방향이다.
- `frame(1/30)`이면 새 방향이 반영되기 전 여러 fixed step이 실행될 수 있어 오차가 렌더 프레임 길이에 의존한다. 록온 완료 직전에는 뒤로 돌아서는 입력에도 조각이 열릴 수 있다.
- 권고: 시선의 기본 방향과 눈 위치를 해당 fixed step의 입력/이동 결과에 맞춰 갱신한 뒤 록온·공격 판정에 사용한다.

## 두 PR 통합 검토

- `git merge-tree --write-tree origin/antigravity/art-fragment origin/claude/gaze-perception`은 exit 0. 원본 브랜치에 병합/커밋하지 않고 반환 tree를 별도 사본에 추출했다.
- 통합 `npm.cmd run build` 통과. PR #7은 `fragments`만 구현하므로 PR #8의 `perception`, `alerts` 등 새 층은 기존 fallback으로 계속 호출된다. 모든 ART_LAYERS 항목에 fallback 함수가 존재한다.
- 확인한 depth: perception 30 → enemies 40 → particles 80 → alerts 90 → fragments 100 → screen 110, debug 1000. 새 조각이 소리/시선 렌더러를 대체하거나 없애는 연결 문제는 없었다. `showArt=false`에서는 LabScene의 기존 fallback 분기가 유지된다.
- 통합 소스에서 PER-1~5의 재현을 다시 실행해 동일 결과를 확인했다. PR #7의 새 조각 렌더러는 PER-5로 잘못 누적된 진행도 역시 그리므로 그 문제를 해결하지 않는다. 이는 PR #8에서 이미 존재하는 문제이며 통합 전용 신규 버그로 중복 계산하지 않는다.
- 정적 검토와 실행한 함수 검사 범위에서 **통합 때문에 새로 생기는 별도 결함은 발견하지 못했다**. 겹친 적/공격 예고의 실제 화면 가독성과 60fps는 브라우저 플레이 검증이 남아 있다.
