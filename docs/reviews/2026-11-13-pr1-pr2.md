## 2. PR #2 — antigravity/sfx-and-amber-hud

### 판정

**중간 심각도 두 사례를 수정한 뒤 재검토를 권장합니다.** 둘은 같은 `hp < lastHp` 설계에서 나온 서로 다른 실패 경로입니다. 이전 리뷰에서 하나로 묶었던 문제를 재현 조건과 영향에 따라 나눴습니다. 높음·낮음으로 분류할 추가 결함은 확정하지 않았습니다.

### 발견 사항 2-1 — 초기화 알림을 실제 피격으로 처리

- **심각도: 중간**
- **위치:** `src/ui/index.ts:98–115`, `src/audio/index.ts:18–19`, `src/audio/index.ts:34–38`
- **발행 근거:** `src/game/sim.ts:140–143`
- **관련 계약:** `docs/EVENTS.md`의 `player:hurt`는 피격뿐 아니라 방 초기화 시 현재 체력도 전달합니다.

`Sim.reset()`은 같은 호출 안에서 `room:reset → gauge:change → combo:change → player:hurt { hp: 5, maxHp: 5 }` 순서로 발행합니다. 두 구독자는 `room:reset`에서 `lastHp = Infinity`로 바꾸므로, 뒤따르는 체력 동기화가 `5 < Infinity`를 만족합니다.

그 결과 첫 방 생성과 R 초기화에 새 HUD의 피격 플래시·흔들림이 발생하고 `hurt` 효과음도 재생 요청됩니다. 최초 로딩 때는 오디오가 잠겨 실제 소리가 나지 않을 수 있지만, 오디오 활성화·디코딩 완료 후 R을 누르는 경우에는 이를 막을 조건이 없습니다. main의 기존 오디오도 초기화에 피격음을 요청했으므로 오디오 오발 자체는 기존 문제의 미해결이고, 피해 없는 초기화에서 HUD 피격 연출이 생기는 부분은 이번 변경으로 추가된 오류입니다. PR 설명의 ‘room:reset 시 피격음 오발 방지’도 구현과 맞지 않습니다.

재현: `initUI`·`initAudio` 구독을 연결한 뒤 `new Sim(bus, input)` 또는 `sim.reset()` 실행. 실제 이벤트 순서에서 `hurt` 재생 요청과 HUD의 `hurt`·`shake` 클래스가 발생함을 확인했습니다.

수정 방향: 초기화 후 첫 `player:hurt`는 체력 표시 동기화로만 소비하도록 구분하세요. 현재 계약과 이벤트 순서만으로 처리할 수 있습니다.

### 발견 사항 2-2 — 체력 1에서 맞으면 피격 효과 누락

- **심각도: 중간**
- **위치:** `src/audio/index.ts:34–38`, `src/ui/index.ts:111–117`
- **발행 근거:** `src/game/sim.ts:683–693`

`checkEnemyHits()`는 체력을 줄인 다음, 0 이하이면 바로 최대 체력으로 회복하고 `player:hurt`를 보냅니다. 체력 1에서 피격되면 구독자가 받는 체력은 0이 아니라 5입니다. 따라서 `hp < lastHp`가 `5 < 1`이 되어 피격 효과를 건너뜁니다.

기존 오디오는 `player:hurt`를 받을 때마다 재생했지만 이번 변경은 이 조건에서 피격음을 생략합니다. 새 HUD의 플래시·흔들림도 생략되어 실제 피격 순간의 피드백이 일관되지 않습니다. 게임 씬의 피격 표시·넉백·히트스톱까지 사라지는 문제는 아닙니다.

재현: 실제 `Sim.checkEnemyHits()`로 무적 시간을 해제하며 다섯 번 피격시켰습니다. 이벤트의 체력은 `4 → 3 → 2 → 1 → 5`였고, 앞선 네 번에는 `hurt` 재생 요청·HUD 플래시가 발생했지만 다섯 번째에는 둘 다 없었습니다.

수정 방향: 2-1의 초기화 동기화를 별도로 구분한 뒤, 그 외 `player:hurt`는 체력이 늘어났더라도 실제 피격으로 처리하세요. 단순히 `Infinity`를 다른 초기값으로 바꾸는 것만으로는 이 사례가 해결되지 않습니다.

### 이벤트 수신 순서·타이밍 대조

`EventBus.emit()`은 `src/core/events.ts:47–55`에서 구독자를 동기 호출합니다. UI·오디오 구독은 `src/main.ts:14–19`에서 씬 생성 전에 연결되므로 초기화 이벤트도 받습니다. 다음은 `sim.ts`의 실제 발행 순서를 기준으로 한 점검입니다.

| 상황 | 실제 발행 순서·시점 | PR #2 구독 처리 점검 |
|---|---|---|
| 방 초기화 | `room:reset → gauge:change(0) → combo:change(0) → player:hurt(최대 체력)` (`sim.ts:140–143`) | 게이지·콤보·다이빙 표시 초기화는 연결됩니다. 체력 효과는 2-1에 해당합니다. 다이빙 도중 R로 초기화하면 `dive:end` 없이 `room:reset`이 오지만 HUD가 직접 오버레이를 닫으므로 종료 이벤트에만 의존하지 않습니다. |
| 일반/자동 회복 피격 | 체력 감소·자동 회복을 적용한 뒤 `player:hurt`, 콤보가 있었다면 이어 `combo:end → combo:change(0)` (`sim.ts:677–697`) | 일반 감소는 처리하지만 자동 회복 피격은 2-2에 해당합니다. 콤보 표시는 `combo:change(0)`으로 닫힙니다. |
| 록온 | 진행 시작에 `lock:progress(0)`, 완료 시 `lock:complete → fragment:open(chained=false)` (`sim.ts:459–479`) | 시작·완료·조각 열림에 각각 대응합니다. 매 프레임 진행 이벤트가 온다고 가정하지 않습니다. 같은 스텝에 완료되더라도 해당 순서로 처리합니다. |
| 조각 만료 | `fragment:close(missed=true) → enemy:telegraph(counter=true)`, 콤보가 있으면 종료 이벤트 (`sim.ts:482–490`) | 놓침음과 반격 예고음은 같은 스텝에서 이어 재생 요청됩니다. 반격 시점을 별도 타이머로 추정하지 않습니다. |
| 연쇄 타격 | 시작 시 `strike:start(chain+1)`. 명중 시 `enemy:down → strike:hit → combo:change → gauge:change`, 만충이면 `dive:ready`, 다음 대상이 있으면 `fragment:open(chained=true)` (`sim.ts:525`, `sim.ts:557–590`, `sim.ts:711–715`) | 시작/명중의 chain 값과 다음 조각의 chained 값을 사용합니다. 다운음·타격음·다음 조각음이 같은 스텝에서 겹칠 수 있지만 이벤트 순서를 역전시키는 처리는 없습니다. |
| 바늘 적중 | 게이지 변경·만충 알림을 먼저 보낸 뒤, 처치하면 `enemy:down`, 마지막에 `needle:hit(killed)` (`sim.ts:399–408`) | `needle:hit`의 killed 값으로 적중음을 선택하므로 `enemy:down` 이후 도착해도 판별이 가능합니다. |
| 게이지 만충 | `gauge:change → dive:ready` (`sim.ts:711–715`) | 게이지·READY 문구가 먼저 갱신되고 준비 펄스가 붙습니다. |
| 고스트 다이빙 | `dive:start`, 약 0.7s 후 대상별 `enemy:down → dive:impact → gauge:change(0) → combo:change`, 약 1.4s 후 `dive:end` (`sim.ts:718–753`) | 오버레이 시작·타격 플래시/격파 수·종료를 각 이벤트에 연결합니다. `dive:impact`에서 바로 닫지 않습니다. 타이머는 `frame()`의 히트스톱 조기 반환보다 먼저 갱신되므로 히트스톱 종료를 기다리지 않습니다 (`sim.ts:168–177`). |

다이빙의 `realDt`를 `1/30`, `1/60`, `1/144`초로 바꿔 실제 `updateDive()`를 실행했습니다. 타격/종료 누적 시각은 각각 `0.7000/1.4000s`, `0.7167/1.4000s`, `0.7014/1.4028s`로 한 호출 간격 이내 오차였고, 이벤트 순서 및 오버레이 종료를 확인했습니다. 이는 브라우저에서 해당 FPS를 강제한 플레이테스트가 아닙니다.

## 검증 범위와 변경 내역

브랜치별 빌드는 임시 디렉터리에 추출한 커밋 사본에서 기존 설치 의존성을 사용했습니다. 위 실행 검증은 해당 브랜치의 실제 `Sim`·`EventBus`·구독 코드를 사용하고 DOM과 효과음 재생기를 대역으로 연결했습니다. 따라서 재생 요청과 DOM 클래스 변화의 검증이며, 실제 브라우저 렌더링·청취·네트워크 로딩 지연·최종 손맛을 보증하지 않습니다. 버퍼 디코딩이 끝나기 전 `Sfx.play()`가 요청을 건너뛰는 처리도 있으므로 실제 청취 시에는 로딩 완료 여부를 함께 확인해야 합니다 (`src/audio/sfx.ts:75–84`).

게임 소스는 수정하지 않았습니다. 이번 요청으로 작성한 파일은 이 리뷰 문서뿐이며, 커밋·PR 댓글 게시·병합은 수행하지 않았습니다.
