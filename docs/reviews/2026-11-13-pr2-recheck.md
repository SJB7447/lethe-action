## 기존 발견 사항의 해결 여부

### 2-1 — 초기화 알림을 실제 피격으로 처리: 해결

- **발행 위치(PR #4, 최신 PR #2 공통):** `src/game/sim.ts:140–143`
- **구독 위치(최신 PR #2):** `src/ui/index.ts:103–114`, `src/audio/index.ts:28–30`
- **계약 위치(PR #4, 최신 PR #2 공통):** `src/core/events.ts:9–10`, `docs/EVENTS.md:11–12`

방 생성·초기화의 발행 순서는 이제 `room:reset → gauge:change(0) → combo:change(0) → player:hp(5/5)`입니다. `player:hurt`는 발생하지 않습니다. UI는 `player:hp`에서 체력칸만 갱신하고, UI·오디오의 피격 효과는 `player:hurt`에서만 실행합니다. 기존 `lastHp`/`Infinity` 비교도 제거됐습니다.

실제 시뮬레이션과 최신 구독 코드를 연결해 첫 생성 및 반복 초기화를 실행했습니다. 체력칸 5개가 채워지고, `hurt` 재생 요청·신규 피격 플래시·흔들림 실행이 발생하지 않았습니다. 다이빙 도중 초기화도 오버레이가 닫히고 체력이 동기화되며 피격음이 요청되지 않았습니다.

### 2-2 — 체력 1에서 피격 시 효과 누락: 해결

- **발행 위치(PR #4, 최신 PR #2 공통):** `src/game/sim.ts:683–695`
- **구독 위치(최신 PR #2):** `src/audio/index.ts:28–30`, `src/ui/index.ts:103–114`
- **순서 계약:** `docs/EVENTS.md:33`

피격 직후 값을 담은 `player:hurt`를 먼저 보낸 뒤, 실험실 자동 회복을 적용하고 표시용 `player:hp`를 보냅니다. 체력 1에서 맞으면 `player:hurt { hp: 0, maxHp: 5 } → player:hp { hp: 5, maxHp: 5 }`가 됩니다. 구독자는 체력의 증감과 무관하게 피격 효과를 실행합니다.

다섯 번 연속 피격을 실제 `checkEnemyHits()`로 실행하여 다음 결과를 확인했습니다.

| 피격 횟수 | `player:hurt.hp` | 뒤따르는 `player:hp.hp` | HUD의 켜진 체력칸 | 피격음 요청·플래시·흔들림 |
|---|---|---|---|---|
| 1 | 4 | 4 | 4 | 각 1회 |
| 2 | 3 | 3 | 3 | 각 1회 |
| 3 | 2 | 2 | 2 | 각 1회 |
| 4 | 1 | 1 | 1 | 각 1회 |
| 5 | 0 | 5 | 5 | 각 1회 |

마지막 피격에 콤보가 있는 조건도 실행했습니다. 순서는 문서대로 `player:hurt → player:hp → combo:end → combo:change(0)`였으며, 체력 표시가 0으로 남거나 피격 효과가 빠지지 않았습니다.

## 추가 확인 사항

### R-1 — PR #4 단독 적용 시 기존 HUD가 체력을 동기화하지 못함

- **심각도: 중간**
- **발행 변경 위치(PR #4):** `src/game/sim.ts:143`, `src/game/sim.ts:693–695`
- **호환되지 않는 구독 위치(PR #4):** `src/ui/index.ts:36–38`
- **발생 범위:** PR #4만 적용한 상태. 최신 PR #2 통합 상태에서는 해결됨.

PR #4의 기존 HUD는 여전히 `player:hurt`로만 체력칸을 그립니다. 초기화 이벤트가 `player:hp`로 바뀌어 첫 화면의 체력칸이 비어 있고, 마지막 체력에서 피격되면 `player:hurt.hp = 0`을 그린 뒤 실제 회복값을 담은 `player:hp`를 무시합니다. 실제 체력이 5로 회복돼도 HUD의 켜진 체력칸은 0개로 남습니다. 두 조건 모두 PR #4의 실제 코드로 재현했습니다.

이는 PR #4 본문에서 이미 안내한 병합 의존성이며, 통합 수정에서 새로 발견한 미해결 결함으로 집계하지 않았습니다. 다만 PR #4를 독립적으로 배포하면 발생하는 실제 기능 회귀이므로 별도 기록합니다. 초기 체력칸뿐 아니라 자동 회복 후 표시에도 영향을 줍니다.

**처리 방향:** 이벤트 생산자와 새 구독자가 함께 들어간 최신 PR #2 통합 상태를 배포 기준으로 삼으세요. PR #4만 병합된 중간 상태가 자동 배포되지 않도록 병합·배포 순서를 조정할 필요가 있습니다. 코드 수정이나 병합은 이번 리뷰에서 수행하지 않았습니다.
