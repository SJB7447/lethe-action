# 그래픽 지침서 — Antigravity + Gemini 4 Hydrogen

레테 2D 액션의 그래픽을 Antigravity에서 **Gemini 4 Hydrogen** 모델로 작업할 때 따르는 규칙입니다.
공통 규칙은 `AGENTS.md`, 역할은 `docs/ROLES.md`가 우선합니다.

> 이 지침은 특정 모델 기능에 기대지 않습니다. 이후 모델을 바꿔도 그대로 적용됩니다.

---

## 1. 왜 이렇게 나누나: "코드로 그리는 그림"을 주력으로

Hydrogen 같은 언어 모델의 강점은 **그림을 코드로 짜는 일**입니다(SVG, Phaser Graphics, 셰이더, 파티클, CSS).
이 방식은 기획안 7장의 AI 에셋 리스크를 그대로 피합니다.

| 기획안의 리스크 | 코드로 그리면 |
|---|---|
| AI 스프라이트의 프레임 간 일관성 | 같은 함수가 매 프레임을 그리므로 형태가 흔들리지 않음 |
| 스타일이 섞임 | 팔레트와 선 굵기를 상수로 고정 |
| 저작권 (사람의 창작 개입) | 형태·색·움직임 규칙을 사람이 정하고, 코드와 수치를 직접 고칠 수 있음 |
| 손맛과 그림이 엉킴 | 그림 함수는 판정을 읽기만 하고 바꾸지 않음 |

그래서 다음처럼 나눕니다.

| 대상 | 방식 | 이유 |
|---|---|---|
| 찢긴 기억 조각, 록온, 균열, 타격·연쇄 이펙트 | **코드 (Phaser Graphics / 셰이더)** | 게임의 정체성. 타이밍과 같이 움직여야 함 |
| 이단아, 보안 요원 (단순 실루엣) | **코드 (벡터 도형 조합)** | 기획안: 실루엣 단순, 프레임 적게 |
| 배경 (마포점 로비 등) | 코드 레이어 + 필요하면 이미지 | 시차 스크롤, 중력 렌즈 왜곡은 코드가 유리 |
| 보스, 컷신 일러스트 | 이미지 생성 도구 (3단계) | 기획안: AI 일러스트는 보스·컷신·배경에 집중 |

이미지 파일을 쓸 때도 아래 4~6장의 규격과 기록 규칙은 똑같이 지킵니다.

## 2. 레테 시각 언어 (스타일 고정)

### 팔레트
챕터 색은 박제실 기억 패널 색을 따릅니다. **아래 값은 임시입니다.** 기획자가 확정한 값이 오면 이 표만 바꿉니다.

| 이름 | 임시 HEX | 쓰임 |
|---|---|---|
| ink (바탕) | `#0b0d14` | 모든 화면의 기본 어둠 |
| amber gold | `#e8b04b` | 챕터 1, **찢긴 기억 조각** (화면에서 가장 눈에 띄어야 함) |
| deep crimson | `#c2334d` | 챕터 2, 균열 보이는 적, 피격 |
| prussian blue | `#1f3a5f` | 챕터 3 |
| pale violet | `#9b7bd4` | 챕터 4, 고스트 다이빙·연결 게이지 |
| deep emerald | `#1f6b52` | 챕터 5, 박제실 |
| player cyan | `#6ee7f2` | 이단아 (임시 식별색) |
| memory white | `#fff1cf` | 균열선, 하이라이트 |

- 색은 코드에 직접 쓰지 말고 `src/art/palette.ts` 한 곳에서 가져옵니다.
- 한 화면에 챕터 색은 **하나만** 주조색으로 씁니다. amber는 챕터와 상관없이 "조각" 전용입니다.

### 물리 기반 시각 언어
| 개념 | 화면 표현 | 쓰는 곳 |
|---|---|---|
| 중력 렌즈 | 대상 주변 배경이 둥글게 휘어 보임 | 록온 중인 적, 고스트 다이빙 진입 |
| 시간 변위 | 잔상, 색 분리(RGB 어긋남), 프레임 끊김 | 대시, 파고들기, 히트스톱 |
| 균열 기하 | 날카로운 직선 조각, 보로노이·삼각 분할 | 찢긴 기억 조각, 적 격파, 무대 장식 |

곡선 장식, 판타지풍 마법진, 귀여운 비율은 쓰지 않습니다.

### 세계관 금지 사항
- **이재환의 얼굴은 어떤 그림에도 그리지 않습니다** (뒷모습, 실루엣, 가림만).
- 서진혁은 고스트 다이빙 때 "연결"로만 등장합니다. 전투 화면에 직접 서 있지 않습니다.
- 실제 기업 로고, 실존 장소의 상표는 쓰지 않습니다.

## 3. 읽기 쉬움이 먼저 (손맛을 해치지 않는 규칙)

예쁜 것보다 **읽히는 것**이 먼저입니다. 아래 순서로 눈에 띄어야 합니다.

1. 열린 찢긴 기억 조각 (amber, 펄스)
2. 적 공격 예고 (깜빡임), 적의 느낌표 (`alerts` 층: 소리로 들음 = amber, 이단아를 봄 = crimson)
3. 이단아 (얼굴과 시선 방향이 읽혀야 함)
4. 적 (보는 방향이 읽혀야 함)
5. 시선 원뿔·소리 범위 (`perception` 층: 흐리게. 판정과 같은 모양이므로 형태를 바꾸지 말 것)
6. 이펙트, 배경

- 균열 있는 적과 없는 적은 **색만이 아니라 실루엣으로도** 구분합니다 (색약 대비).
- 이펙트가 조각이나 공격 예고를 가리면 안 됩니다. 파티클은 반투명, 조각보다 아래 층에 그립니다.
- 배경은 명도를 낮게 유지합니다 (ink 위 10~20% 밝기). 캐릭터보다 밝은 배경은 금지.
- 히트스톱 중에도 그림은 멈춥니다. 시간 기준 애니메이션은 게임이 넘겨주는 시간값을 씁니다(실제 시계 금지).
- 성능 예산: 960×540에서 60fps 유지. 동시 파티클 300개 이하, 전체 화면 셰이더는 1개까지.

## 4. 판정과 그림 분리 (절대 규칙)

충돌 판정 크기는 그림과 무관하게 고정입니다. 그림은 판정 박스를 **기준점에 맞춰 덮기만** 합니다.

| 대상 | 판정 박스 (px) | 그림 프레임 권장 (px) | 기준점 |
|---|---|---|---|
| 이단아 | 22 × 40 | 48 × 64 | 판정 박스 아래 가운데 = 그림 아래 가운데 |
| 지상 보안 요원 | 30 × 44 | 56 × 64 | 같음 |
| 비행 보안 요원 | 30 × 30 | 48 × 48 | 판정 박스 중심 = 그림 중심 |

- 그림이 판정보다 조금 커도 되지만, 판정 밖으로 **공격처럼 보이는 부분**(팔, 무기)이 나가면 안 됩니다.
- 디버그 표시(`` ` `` 키)와 판정 박스 보기는 항상 그림 위에 겹쳐 확인할 수 있어야 합니다.
- 그림 코드에서 위치·속도·상태를 **바꾸지 않습니다**. 읽기만 합니다.

### 캐릭터 동작 프레임 수 (상한)
코드로 그리면 프레임 대신 "포즈 + 보간"을 쓰지만, 이미지로 만들 때는 아래를 넘지 않습니다.

| 동작 | 이단아 | 보안 요원 |
|---|---|---|
| 대기 | 4 | 4 |
| 달리기 / 순찰 | 6 | 4 |
| 점프·낙하 | 2 + 2 | — |
| 벽 미끄러짐 | 2 | — |
| 대시 | 3 | — |
| 파고들기 | 3 | — |
| 피격 | 2 | 2 |
| 공격 예고 / 돌진 | — | 3 / 2 |
| 쓰러짐 | — | 4 |

## 5. 폴더와 연결 방법

| 경로 | 담당 | 내용 |
|---|---|---|
| `src/art/` | Antigravity | 그림 코드 (팔레트, 캐릭터·적·조각·이펙트·배경 그리기 함수) |
| `public/assets/art/` | Antigravity | 이미지 파일 (`bg/`, `boss/`, `cutscene/`, `fx/`) |
| `docs/art/AI_LOG.md` | Antigravity | AI 생성 기록 (6장) |
| `src/scenes/` | Claude | 그림 함수를 호출하는 쪽 |

- `src/art/`는 `src/game/`의 **타입만** import할 수 있습니다 (`import type`). 함수나 상태 객체를 직접 바꾸지 않습니다.
- 그림 함수의 모양(입력·출력)은 Claude가 `src/art/contract.ts`로 정합니다. 내용은 자유입니다.
- **`contract.ts`가 아직 없으면** `src/art/`에 그리기 함수만 만들고 `src/scenes/LabScene.ts`는 고치지 마세요.
  게임 화면 연결은 `docs/REQUESTS.md`에 요청하면 Claude가 합니다.
- 새로 필요한 상태값(예: 적의 공격 예고 남은 시간)은 `docs/REQUESTS.md`에 요청합니다.
- 언제든 임시 사각형 그림과 비교할 수 있도록 `?art=0` 주소로 그림을 끌 수 있게 유지합니다.

파일 이름: 소문자 + 밑줄. 예) `enemy_guard_idle.png`, `bg_ch1_lobby_far.png`, `fx_fragment_open.ts`

## 6. AI 생성 기록 (스팀 공개 표시·저작권 대비)

스팀은 플레이어에게 보이는 AI 생성 콘텐츠를 표시해야 합니다. 출시 때 정확히 쓰려면 지금부터 기록합니다.
화면에 보이는 그림을 만들거나 크게 바꿀 때마다 `docs/art/AI_LOG.md`에 한 줄 추가합니다.

```
| 날짜 | 파일 | 도구·모델 | 무엇을 만들었나 | 사람이 정한 것 / 고친 것 |
| 2026-11-14 | src/art/fragment.ts | Antigravity + Gemini 4 Hydrogen | 조각 펄스·균열선 그리기 코드 | 형태 규칙, 색, 펄스 속도 지정 / 균열선 각도 수정 |
```

"사람이 정한 것" 칸이 저작권 판단의 근거가 됩니다. 비워 두지 않습니다.

## 7. 작업 흐름

1. 브랜치: `antigravity/art-…`
2. `npm run dev`로 띄우고 **그림을 켠 상태와 끈 상태(`?art=0`)를 둘 다** 플레이해 봅니다.
3. 판정 박스 보기를 켜고 4장 표대로 맞는지 스크린샷으로 확인합니다.
4. `npm run build` 통과 → PR. PR에는 전·후 스크린샷과 AI_LOG 추가 줄을 넣습니다.
5. Codex 리뷰 기준에 그림 항목이 추가됩니다: 판정 변경 여부, 3장 읽기 순서, 성능 예산, AI_LOG 누락.

## 8. 첫 작업 목록 (우선순위 순)

| 순서 | 대상 | 완료 기준 |
|---|---|---|
| 1 | `src/art/palette.ts` | 2장 팔레트를 상수로 정의, 기존 하드코딩 색을 대체할 수 있음 |
| 2 | 찢긴 기억 조각 + 록온 | 록온 진행 → 균열이 번지며 열림 → 남은 시간 표시. 화면에서 가장 먼저 보임 |
| 3 | 파고들기·타격 이펙트 | 시간 변위(잔상, 색 분리) + 균열 파편. 연쇄 수에 따라 강해짐 |
| 4 | 이단아 실루엣 | 4장 규격, 동작별 포즈 구분, 방향 전환이 한눈에 보임 |
| 5 | 보안 요원 2종 실루엣 | 균열 있음/없음을 실루엣으로 구분 |
| 6 | 챕터 1 배경 (레테 마포점 로비) | 3층 시차 스크롤, 명도 규칙 준수 |
